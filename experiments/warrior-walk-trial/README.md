# 전사 6방향 이동 스프라이트 시험

상태: IMPLEMENTED_UNVERIFIED. 사용자 수동 빌드·실기기 평가 대기.

- 적용 대상: Warrior의 헥사 월드 이동 표시만.
- 리소스: res/warrior_walk_trial.png, 420×280 투명 PNG. 70×70 셀, 6열×4행.
- 열 순서: E(+1,0), NE(+1,-1), NW(0,-1), W(-1,0), SW(-1,+1), SE(0,+1).
- 행: 접지→교차→반대발 접지→반대 교차의 4프레임. 월드 50ms 틱 2회마다 교대(100ms/프레임, 전체400ms).
- 정지·일시 정지·전투·HUD는 원본 warrior.png 사용. 다른 직업과 몬스터는 기존 표시 유지.
- 제작: built-in image_gen 도구. 원본 스타일을 참고한 atlas 생성 후 방향 구분을 한 차례 수정. 초기 프롬프트는 PROMPTS.md, 다리 교차 수정은 PROMPTS-v2.md. generated-atlas-v2.png는 현재 고해상도 원본이며 게임에는 작은 res atlas만 등록.
- 에셋 준비: System.Drawing으로 실제 프레임 행을 분리해 공통 비율로 축소하고 발 기준선64px/투명 여백으로 정렬(prepare-v2.ps1). 원본 warrior.png는 변경하지 않았으며 백업과 SHA256 일치.
- 검증: 24셀 모두 비어 있지 않고 경계가 투명, PNG 크기/원본 해시/소스 인코딩·구조/방향 매핑/두 월드 렌더 경로/JDP 등록 정적 확인. 빌드·게임 실행 미수행.

## 실기기 확인

1. Space로 Warrior 턴까지 넘기고 보이는 육지에서 각 방향으로 이동한다.
2. 직선과 꺾이는 경로에서 진행 방향 및 4프레임 다리 교차·양발 교대 확인.
3. 같은 타일의 동료와 분리 이동, 기습/도망 후 이동 재개, 전투·마을 진입 시 표시 확인.
4. 백그라운드 후 복귀 시 이동/프레임이 정지 상태에서 이어지는지 확인.
5. 원본과의 크기·스타일 일치, 작은 화면에서 걸음 구분·방향 판독·속도 체감 평가.

## 되돌리기

빠른 비활성화: Unit.java의 WARRIOR_WALK_TRIAL을 false로 바꾼 후 수동 빌드. 원본 스프라이트로 표시된다.

완전 revert용 변경 전 파일은 before/Unit.java, before/HexGameScreen.java, before/Cave.jdp에 보관했다. before/warrior.png는 원본 보존 확인용이다. 이후 다른 작업이 진행되었다면 백업 전체 덮어쓰기는 그 변경을 잃을 수 있으므로 이 시험 변경만 선택적으로 되돌린다. 시험 소스 변경과 JDP의 res/warrior_walk_trial.png 등록을 제거하면 게임은 추가 atlas를 사용하지 않는다. 다른 청크의 진행 상태는 유지한다.
수정 이력: 사용자 지적에 따라 한쪽 다리만 들리는 2프레임을 4프레임 걷기 순환으로 교체. 초기 시험 에셋은 warrior-walk-v1.png로 보관했다. 24프레임 모두 투명 경계·원본 보존 확인, 실기기 걸음 평가는 대기.
